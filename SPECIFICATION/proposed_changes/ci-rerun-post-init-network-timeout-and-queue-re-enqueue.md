## Proposal: CI re-run reconciler covers post-init network connect timeouts and re-enqueues a queue-ejected pull request once

### Target specification files

- SPECIFICATION/non-functional-requirements.md

### Summary

Add two re-run classes to the CI infrastructure re-run reconciler paragraphs of non-functional-requirements.md section 'Hooks and CI', beside the three that exist (the `Set up job` 429 class, the `Initialize containers` registry-error class, the job-creation `Internal server error` class). (1) A gating CI job that fails at a setup step after `Initialize containers` (for example `Prepare workspace`) with a network connect timeout in that step's log, before any test step, is re-run once, starting within 5 minutes. (2) A pull request that a merge_group run ejected from the merge queue because a job of that run failed with one of the infrastructure classes, and that is mergeStateStatus CLEAN with no queue entry, is re-enqueued once, within 10 minutes of the ejecting run completing. The section's shape is kept: bounded count, classifier-keyed and never keyed on a test failure, a MUST NOT for non-matching failures whose failure stays the verdict, and the reconciler's own run-summary record. No heading is added, renamed or removed.

### Motivation

Measured occurrence: livespec-orchestrator-beads-fabro#5633 was ejected from the merge queue by merge_group run 44881296011 (runner livespec-orchestrator-k3s-j9j6s-runner-q2mvf, job check-per-file-coverage (nonroot), step 'Prepare workspace (git trust, mise trust + install, uv sync)', 07:53:36Z, 'fatal: unable to access https://github.com/livespec-ai/livespec-dev-tooling.git/: Failed to connect to github.com port 443 after 135602 ms', exit 128), after which ci-green failed. The pull request's own 22 checks passed, auto-merge was cleared by the ejection, and the PR sat mergeStateStatus CLEAN with no queue entry for about 55 minutes until a human re-queued it. The failure happened after `Initialize containers` and before any test step, so none of the three existing classes matched it, and no automation recovered the queue entry.

The cause is NOT measured: neither the node nor the network cause of the connect timeout has been measured. The fix is classifier-keyed on the log signature and the ejection state, and makes no claim about the cause. If a cause is later measured and fixed, the classes remain correct as a bounded safety net.

Count rationale: the post-init timeout class re-runs ONCE, with the same 5-minute start bound as the registry class. A connect timeout of this kind already waited about 135 seconds before failing, so one re-run on a fresh connection is the proportionate response; a second consecutive timeout points at a persistent network fault that a third blind attempt would only hide, so the second occurrence stays the run's verdict and is recorded as left for its owner (the registry class uses the same count for the same reason). The re-enqueue is likewise once per pull request and signature, so a repeating ejection reaches its owner.

Fleet scope: every repository that adopts the reconciler; the re-enqueue class applies to every such repository that has a merge queue. Work item: livespec-dev-tooling-nqdcna ('A pull request the merge queue ejected on an infrastructure failure is re-enqueued once by the merge-poll reconciler'). Ruled by legacy-coordinator-agent (R301, 2026-11-21).

### Proposed Changes

In SPECIFICATION/non-functional-requirements.md section "Hooks and CI", add the following two paragraphs immediately after the paragraph that begins "A gating CI run of a fleet repository that adopts the CI infrastructure re-run reconciler and that GitHub fails at job creation" and before the "**Workflow files must parse.**" paragraph:

```
A gating CI job of a fleet repository that adopts the CI infrastructure re-run reconciler (contracts.md section "Reusable workflows wire contract", `reusable-ci-infra-rerun.yml`) and that fails at a setup step that runs after `Initialize containers` and before any test step (for example `Prepare workspace`), with a network connect timeout in that step's log, MUST be re-run automatically once. The network connect timeouts are `Failed to connect to <host> port <n> after <ms> ms`, `Connection timed out`, or `i/o timeout`, in each case against github.com. The reconciler MUST start the re-run within 5 minutes of the failed run completing. A job that fails at a test step or at any later step, a setup-step failure that carries no such timeout line, a timeout against a host other than github.com, and a job already re-run once for this cause MUST NOT be re-run by this mechanism, and its failure MUST stay the run's verdict. The classification is keyed on the step and the log signature and never on a test failure. Each such re-run MUST write the run id, the job id and the matched error line to the reconciler's own run summary. Each failure the reconciler leaves MUST be recorded in that summary as left for its owner. The summary line is the occurrence record, so a matched re-run owes no per-occurrence flake work item.

A pull request that a merge_group run of a fleet repository that adopts the CI infrastructure re-run reconciler and has a merge queue ejected from the queue, because a job of that run failed with an infrastructure class that this section names, and that is mergeStateStatus CLEAN with no merge-queue entry, MUST be re-enqueued automatically once. The reconciler MUST re-enqueue it within 10 minutes of the ejecting run completing. The failure is infrastructure when the failed job matches the `Set up job` rate-limit class, the `Initialize containers` registry-error class, or the post-init network connect timeout class of this section; a failure of a test or check assertion MUST NOT be re-enqueued by this mechanism. A pull request that is not CLEAN, a pull request that already has a queue entry, and a second ejection of the same pull request for the same signature MUST NOT be re-enqueued by this mechanism. A second ejection MUST be recorded in the reconciler's own run summary as left for its owner. Each re-enqueue MUST write the repository, the pull request number, the ejecting run id and the matched signature to that summary. The summary line is the occurrence record, so a matched re-enqueue owes no per-occurrence flake work item.
```

Implementation consequence (not edited by this proposal): contracts.md section "Reusable workflows wire contract" describes `reusable-ci-infra-rerun.yml` as re-running only a job whose failure matches "a re-run signature that non-functional-requirements.md section 'Hooks and CI' names", and as classifying run-level job-creation failures. The job-class wording picks up the new post-init timeout class by reference and needs no edit. The reusable workflow's present contract has no merge-queue behavior: it neither reads merge_group ejections nor enqueues a pull request, and its inputs are `run_id` only and its `actions: write` grant does not cover enqueueing. The re-enqueue class therefore needs a contract amendment (a merge-queue ejection input or a merge_group trigger, the permission to enqueue, and the count of pull requests re-enqueued and left among its outputs), which the implementation work item livespec-dev-tooling-nqdcna carries as a follow-on propose-change once the realization shape (extending the reusable workflow or a merge-poll reconciler step) is chosen. No `## ` heading is added, renamed or removed, so tests/heading-coverage.json needs no edit.
