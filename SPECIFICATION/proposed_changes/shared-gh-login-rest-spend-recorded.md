## Proposal: The shared GitHub login's REST spend is recorded per caller on the dev hosts

### Target specification files

- SPECIFICATION/non-functional-requirements.md

### Summary

Add one obligation under Host provisioning tree. This repository ships a role that records the shared GitHub user login's REST spend, and `ansible/dev-host.yml` applies it to `dev_hosts`. The role has a once-a-minute rate-limit sampler and a `gh` wrapper that records each REST request with caller, host, time and endpoint. A per-caller, per-hour report reconciles against the sampled budget and shows the unrecorded remainder as an unattributed row. Logs are rotated to 14 days, and the login is an asserted out-of-band precondition.

### Motivation

On 2026-11-13 the shared `gh` user login's REST `core` budget read 0/5000 from 21:56Z to 22:30Z. Factory launches bounced at the master-CI preflight for about 33 minutes, and commit gates failed `check-master-ci-green`. A second exhaustion on the VPS near 04:31Z on 2026-11-14 surfaced as a false Fabro-currency dispatch refusal (livespec-orchestrator-beads-fabro bd-ib-kvy72t). About 30 agent seats on several hosts, plus the factory launcher's preflight, spend that one bucket, and GitHub does not attribute spend per caller. A one-host look-back found hetzner-xubuntu spent only about 100 to 150 REST requests over 20:00 to 23:00Z on 2026-11-13. A live reading at 00:00Z on 2026-11-14 showed about 2,100 requests per hour, over 95% of it from other hosts (livespec plan/github-request-budget-discipline/research/02-caller-inventory-2026-11-14.md). Nothing in the fleet can say which caller spent it, which blocks every mitigation under livespec-j49m's measure-before-mitigating disposition. Counting invocations would undercount the leading suspect, because `gh run watch` polls REST every 3 seconds by default from one invocation. This ruling governs livespec-dev-tooling-w4dicq, which builds the gh_request_ledger role in ansible/. Its pre-dispatch Definition-of-Done judgement at 2026-11-14T07:20:54Z found no ratified clause stating the sampler, wrapper and report behaviour. The clause sits under Host provisioning tree because that section already governs roles that install onto provisioned hosts, and their out-of-band preconditions. Plan github-request-budget-discipline (livespec epic livespec-httc), throughput track rank 10.

### Proposed Changes

In non-functional-requirements.md section "Host provisioning tree", insert this paragraph directly after the paragraph beginning **A held service is still installed by a role.**, so that the sentence "This obligation and the next are judged by review and by the drift and apply runs" in **Out-of-band preconditions fail at the start.** keeps naming that held-service paragraph as "the next":

> **The shared GitHub login's REST spend is recorded per caller.** Agent sessions, meaning the Claude, Codex and pi sessions that run on a host, call GitHub through the `gh` command under one shared GitHub user login. This repository MUST ship a role that records that login's REST spend, and `ansible/dev-host.yml` MUST apply it to the `dev_hosts` group. A host provisioned outside this tree MAY consume the role at a pinned commit; that host's own provisioning, not this repository, then applies and verifies it. The role MUST install a sampler that, at least once a minute, appends to a durable per-host sample log one JSON line holding the login's REST `core` and GraphQL used, remaining and reset values, read from the rate-limit endpoint alone, which spends no budget. It MUST install a wrapper ahead of the real `gh` on the agent sessions' PATH. The wrapper MUST append to a durable per-host request log one line for every HTTP request a wrapped `gh` process makes to the REST API, so that a long-running `gh` process yields one line per request rather than one per invocation. Each line MUST hold a caller label, the host, a UTC timestamp and the endpoint. The caller label MUST name the session or service that ran the command, falling back to the parent process name when none is named. The wrapper MUST pass each wrapped command's arguments, exit status, standard output and standard error through unchanged. A report command MUST print, for a chosen UTC day within the retained logs, REST requests per caller per UTC hour beside the rise in the login's REST `core` used that the sample log shows for that hour. For an hour that spans a budget reset, the rise MUST be the sum of the increases within each reset window. The report MUST also print, for each hour, an unattributed row equal to that rise minus the recorded requests. The request log and the report exclude GraphQL requests, which draw on a separate budget, and requests that a process makes with the login's token without `gh`, which surface only in the unattributed row. The role MUST rotate the sample log and the request log so that a host keeps at most 14 days of each. The shared login is an out-of-band input under **Out-of-band preconditions fail at the start.**: the role MUST assert it before its first task that changes the host, and a converge without it MUST fail at that assert naming the missing login. This obligation is judged by review and by the drift and apply runs; it is not a member of the `just check` aggregate.

No `## ` heading is added, changed or removed, so tests/heading-coverage.json needs no co-edit.
