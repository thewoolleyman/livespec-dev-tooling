## Proposal: delegated-suite-green-worker-count-follows-the-job

### Target specification files

- SPECIFICATION/contracts.md
- SPECIFICATION/scenarios.md

### Summary

In section "Delegated commit-time replay test runs", the "Replay Job size" bullet is amended so that the pytest-xdist `-n` of a DELEGATED suite-green leg comes from the Job's declared `gate_parallelism` (default 4), never from the committing host's CPU count, with an explicit `LIVESPEC_TEST_PARALLELISM` read on the committing host still deciding it. One scenario states the behaviour.

### Motivation

The clause now says a suite-green leg Job runs with the `-n` the replay gate selected on the committing host, that the pytest invocation including that `-n` MUST stay the replay gate's own invocation ("What the Job runs"), and that the `LIVESPEC_TEST_PARALLELISM` the Job exports is inert. Measured 2026-11-19 (livespec-dev-tooling-wg4a2x): the replay gate selects `-n` as max(1, visible_cpus // 4) on the committing host (livespec_dev_tooling/checks/_red_green_replay_suite_argv.py, lane_worker_count). The dev host has 64 CPUs, so the Job is told `-n 16` and runs in a container limited to 8Gi. Job gate-livespec-dev-tooling-xgf8d (poweredge, clean master, full suite at -n 16) peaked at 8,589,946,880 bytes (the limit) with oom_kill 5 and five killed xdist workers rerun; the same suite at -n 4 peaks 4.12 GiB with oom_kill 0. Six commit gates in 24 hours reached 7.56-7.87 GiB and the intermittent failures follow. The clause as ratified is faithful to the code and is the cause: it ties the Job's worker count to a machine that has no relation to the Job's memory. WHICH IS WRONG: neither the clause nor the code misdescribes the other; they speak of two different variables. The clause's 'inert' concerns the LIVESPEC_TEST_PARALLELISM value the JOB exports, which the Job's `-n` overrides. The interim workaround exports the variable on the COMMITTING host, where lane_worker_count reads it first (before the visible_cpus rule), so the replay gate selects `-n 4`. Measured: the commit gate's own log carried `-n 4` with the variable exported (run 20261119T085318Z-2393044, replay Job gate-livespec-dev-tooling-xh7cl: 13483 passed, no reruns, 3.96 GiB working set) and `-n 16` without it. The defect to correct is therefore the clause's design, a worker count that ignores the Job's size, not a mismatch between spec and code.

### Proposed Changes

(1) In SPECIFICATION/contracts.md section "Delegated commit-time replay test runs", bullet **Replay Job size**, replace the sentences from "A suite-green leg Job runs pytest-xdist with the `-n` worker count that the replay gate selected on the committing host." through "The `LIVESPEC_TEST_PARALLELISM` value such a Job exports is therefore inert, because its `-n` governs." with: "A suite-green leg Job runs pytest-xdist with an `-n` worker count that the replay gate selects on the committing host from the Job's own size, never from the committing host's CPU count: the `LIVESPEC_TEST_PARALLELISM` value set in the committing host's environment when it is non-empty, else the repository's declared `gate_parallelism`, else `4`, the renderer's default. A delegated leg MUST NOT select its worker count from the committing host's CPU count; a leg that runs locally keeps selecting it from the CPUs of the host it runs on. It MUST request the declared `gate_cpu` and `gate_memory`, or the defaults when they are absent, as a full-size gate Job does. Its pytest invocation, including that `-n`, MUST stay the replay gate's own invocation, as **What the Job runs** requires. The `LIVESPEC_TEST_PARALLELISM` value such a Job exports is inert, because its `-n` governs." The closing spec-first sentence of the bullet is kept. (2) In SPECIFICATION/scenarios.md add one scenario, immediately after the scenario that states the default gate Job size: "## Scenario: a delegated suite-green replay leg runs pytest with the Job's declared worker count, not one derived from the committing host's CPU count". Given a consuming repository that sets delegated_commit_tests = true and declares gate_parallelism = 6 and a committing host that exposes 64 CPUs with LIVESPEC_TEST_PARALLELISM unset; When the replay gate delegates a suite-green leg; Then the pytest invocation the Job runs MUST carry `-n 6`, and with gate_parallelism undeclared it MUST carry `-n 4`, and with LIVESPEC_TEST_PARALLELISM set to 2 on the committing host it MUST carry `-n 2`, and in every case the `-n` MUST NOT be 16. HEADING COVERAGE: this proposal adds one `## ` heading (the scenario above) to scenarios.md and changes no other `## ` heading, so the revise commit owes one tests/heading-coverage.json row for it; the owed test is at the unit and consumer tier and livespec-dev-tooling-ovzmcn owns it (its References line repoints to this heading after ratification).
