## HALT-first preconditions

Verify in order. Stop on the FIRST failure and report the failing check
plus the exact expected name. Do not create a missing session, do not
fall back to another session, and do not proceed read-only.

**tmux resolves `-t <name>` by exact match THEN PREFIX match.**
`worker_session` is always a strict prefix of `supervisor_session`, and
precondition 4 REQUIRES the supervisor session to exist — so the bare
`has-session -t "$worker_session"` form can never detect a missing
worker, and the follow-on `ps` then reports the SUPERVISOR's own agent
as the worker's driver.

```sh
REPO=/data/projects/livespec-dev-tooling
W='=sandbox-image-tmux:'                    # trailing colon REQUIRED
S='=sandbox-image-tmux-supervisor:'
```

`-t '=name'` WITHOUT the trailing colon silently returns EMPTY format
fields, and an empty value laundered through `readlink -f` becomes a
false PASS. Every consumer below is empty-guarded.

1. **Worker session exists** — exact match only:

   ```sh
   tmux list-sessions -F '#{session_name}' | grep -qx 'sandbox-image-tmux' \
     || echo "HALT: expected session 'sandbox-image-tmux' does not exist"
   ```

   Missing worker is a BOOTSTRAP condition, not a dead-end: ask the
   maintainer ONE recommended-first question offering to start it —

   ```sh
   tmux new-session -d -s sandbox-image-tmux -c "$REPO"
   tmux send-keys -t '=sandbox-image-tmux:' -- 'claude --dangerously-skip-permissions'
   tmux send-keys -t '=sandbox-image-tmux:' Enter
   ```

   — then re-run checks 2–5. Never auto-spawn it.

2. **Worker is a DISTINCT session from you:**

   ```sh
   wpid=$(tmux display-message -p -t "$W" '#{pane_pid}')
   spid=$(tmux display-message -p -t "$S" '#{pane_pid}')
   [ -n "$wpid" ] && [ -n "$spid" ] && [ "$wpid" != "$spid" ] \
     && echo "PASS: worker=$wpid supervisor=$spid" \
     || echo "HALT: worker target resolved to the supervisor's own pane"
   ```

3. **A live AGENT, not a shell** — from exact live process evidence,
   NEVER from a session name:

   ```sh
   [ -n "$wpid" ] || { echo "HALT: empty pane_pid"; exit 1; }
   ps -o pid=,comm=,args= --ppid "$wpid" --pid "$wpid" -H
   # PASS only on a live `claude` or `codex` process; a lone shell is a HALT.
   ```

   Report which driver was found; confirm the pid is not your own.

4. **Supervisor session exists** — exact match only:

   ```sh
   tmux list-sessions -F '#{session_name}' \
     | grep -qx 'sandbox-image-tmux-supervisor' \
     || echo "HALT: expected 'sandbox-image-tmux-supervisor'"
   ```

   A different seat name is a bootstrap condition — rename or proceed
   noting it. HALT only on discovering you are IN the worker pane.

5. **Thread exists in the target repo, and the worker's cwd resolves

## How to inspect and drive

Inspect read-only:

```sh
tmux capture-pane -p -t "$W" -S -40
```

**`-S -N` is NOT "the last N lines."** It is `min(N, available
scrollback)` PLUS the entire visible pane. For a bounded view, capture
the visible pane only (`capture-pane -p`, no `-S`).

Short instruction — send, VERIFY, then Enter SEPARATELY. The one-shot
`… -- '<line>' Enter` form lands the text but does NOT submit it:

```sh
tmux send-keys -t "$W" -- '<one line>'
tmux capture-pane -p -t "$W" | tail -8
tmux send-keys -t "$W" Enter
```

Longer text — load, paste, VERIFY the `[Pasted text]` chip, then Enter:

```sh
tmux load-buffer -b sit /tmp/msg.txt
tmux paste-buffer -b sit -t "$W"
tmux capture-pane -p -t "$W" | tail -8
tmux send-keys -t "$W" Enter
```

Re-check for an open picker before EVERY paste, anchored at BOTH ends —
a substring scan matches prose that merely DISCUSSES pickers, and a
start-only anchor still fires on a wrapped continuation line:

```sh
tmux capture-pane -p -t "$W" | tail -8 \
  | grep -qE '^[[:space:]]*Enter to (select|confirm)[[:space:]]*(·.*)?$' \
  && echo "PICKER OPEN — do not paste"
```

Never answer a picker via its "Type something" option from tmux — it
cancels the batch. Input queued while the worker is legitimately
mid-turn is normal and is consumed at turn end (`Press up to edit queued
messages`); idle PLUS queued input means STUCK. Distinguish idle-done
from wedged by `stop_reason` in the newest transcript under
`~/.claude/projects/-data-projects-livespec-dev-tooling/`, not by
silence; recovery from a hung turn takes TWO Escapes.

Never name a shell variable `TMUX`; never `kill-server` on the
maintainer's socket.

**Never kill the acting overseer daemon.** It runs in tmux
`livespec-overseer:1.1`, supervises every tracked session in the fleet,
and is the shipped product rather than part of any one thread. Every
other rule here protects the one track you govern; this is the only one
whose blast radius is the whole fleet.

## Obligation record

Maintain `$supervisor_marker`, and rewrite it whenever your obligations
change. It must always answer three questions — **what am I waiting on,
what will wake me, and what happens if nothing does.**

```sh
mkdir -p "$REPO/tmp/overseer/sandbox-image-tmux"
cat > "$REPO/tmp/overseer/sandbox-image-tmux/.supervisor-state" <<EOF
updated: $(date -u +%Y-%m-%dT%H:%M:%SZ)
armed_watcher: <background task id, or none>
open_obligations:
  - id: <slug>
    holder: <me|worker|peer-supervisor:SESSION|maintainer>
    waiting_on: <the concrete event>
    wake_mechanism: <the ARMED thing>
    if_nothing_happens: <the escalation, with a deadline>
EOF
```

An obligation with `wake_mechanism: none` is a stall with a timestamp.

## Never end a turn without an armed re-entry

The trigger is **ANY open obligation, whoever holds it** — not merely
"the worker is mid-flight." A correctly parked worker plus a supervisor
holding an open obligation matches no worker-centric trigger.

- The worker is an EXTERNAL tmux session. Its completion emits NO
  notification.
- A status report is not a work product that can end a turn.
- "I'll check back" is an INTENTION, not a mechanism.
- An open `AskUserQuestion` suppresses the daemon's wrap-up injection,
  so the condition most needing attention mutes the only other watcher.

Arm ONE per obligation and record which in `$supervisor_marker`.

**(a) Pane watcher** — primary, for a worker mid-flight. Detect busy by
pane CHANGE, not by a status string:

```sh
prev=""; stable=0
for i in $(seq 1 180); do                    # ~60 min ceiling
  sleep 20
  pane=$(tmux capture-pane -p -t '=sandbox-image-tmux:')   # visible only
  [ -z "$pane" ] && { echo "WAKE: pane unreadable"; exit 0; }
  if printf '%s\n' "$pane" | tail -8 \
       | grep -qE '^[[:space:]]*Enter to (select|confirm)[[:space:]]*(·.*)?$'; then
    echo "WAKE: picker open"; exit 0
  fi
  if [ "$pane" = "$prev" ]; then stable=$((stable+1)); else stable=0; prev="$pane"; fi
  [ "$stable" -ge 3 ] && { echo "WAKE: pane unchanged ~60s — idle"; exit 0; }
done
echo "WAKE: watcher ceiling reached — RE-ARM NOW"
```

**(b) Condition watcher** — for a NON-pane event (a PR merging, a
release publishing, a pin bump landing, a peer replying):

```sh
for i in $(seq 1 180); do
  sleep 20
  if <condition-command>; then echo "WAKE: condition met"; exit 0; fi
done
echo "WAKE: condition watcher expired — RE-ARM NOW"
```

**(c) A long `ScheduleWakeup` (1200s+)** — backstop only.

**Expiry is itself a wake.** Both watchers EXIT on ceiling with a
`WAKE:` line rather than looping silently. Run them with
`run_in_background: true`; do NOT spawn a second shell to poll the
first.

**A watcher on a deliberately PARKED worker is not required** — if the
only wake condition is an event another track produces, arm the watcher
on *that* event or accept the peer track's watcher as the mechanism, and
record which in the marker. The rule is that a wake must EXIST, not that
it must watch your own pane.

**A wake channel must have a referent that something feeds.** If you
name `$wait_channel`, create it at boot and instruct the worker to
append at every milestone.
